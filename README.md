# 直播导播流程单 · Live Rundown

给直播导播团队的节目流程单：临时延长采访或插入内容时，立刻看到后续环节如何变化——
**整体顺延、缓冲被消耗、可压缩环节被压缩、固定开播点绝不被越过；实在放不下时明确报出冲突，而不是让环节悄悄重叠。**

- React 18 + TypeScript + Vite
- 数据保存在浏览器本地（`localStorage`），无需后端
- 撤销 / 重做（时间、缓冲、压缩与冲突状态一起恢复）
- 按秒比例的时间轴 + 播放头预演（1× / 2× / 4× / 8× 倍速）

## 运行

需要 Node.js 18+。

```bash
npm install
npm run dev        # 启动开发服务器（默认 http://localhost:5173）
```

生产构建与预览：

```bash
npm run build      # 先 tsc 严格类型检查，再 vite 构建到 dist/
npm run preview    # 本地预览生产包
```

测试：

```bash
npm test           # 一次性运行全部 vitest 用例
npm run test:watch # 监听模式
```

## 内置 30 分钟直播样例

以 10:00 为开播零点：

| 时间（计划） | 环节 | 时长 | 说明 |
|---|---|---|---|
| 10:00 | 开场 | 2:00 | |
| 10:02 | 新闻速览 | 5:00 | 不可压缩 |
| 10:07 | 嘉宾采访 | 6:00 | 可压缩，下限 3:00 |
| 10:13 | 缓冲段 | 2:00 | 可降至 0:00 |
| **10:15** | **现场连线** | 6:00 | **⚑ 固定开播点** |
| 10:21 | 评论员点评 | 6:00 | 可压缩，下限 4:00 |
| 10:27 | 片尾 | 3:00 | 10:30 准点结束 |

可随时用右上角「重置样例」恢复。

### 验收场景：采访延长 4 分钟

把「嘉宾采访」的计划时长从 6:00 改成 **10:00**（输入 `10` 表示 10 分钟，也支持 `m:ss`）：

1. 前方内容超时 4:00，窗口在 10:15 固定点截止；
2. 系统先吃**缓冲**：2:00 缓冲全部消耗（时间轴上缓冲段缩成一条细标记，「缓冲余量」变为 `0:00 / 2:00`）；
3. 还差 2:00，再**压缩采访本身**：实际 10:00 → 8:00（仍高于 3:00 下限），行内显示 `−2:00`、时间轴左边框变虚线；
4. 「现场连线」**仍在 10:15 准点开始**，评论与片尾时间不变，**片尾仍 10:30 结束**；
5. 绿色「已消化」卡片列出每一笔消化量；固定点前多出的 4:00 以斜纹「空闲等待」表示（消化后前方实际只用了 11:00）。
6. 按 **↶ 撤销**（或 Ctrl/⌘+Z）：缓冲恢复 2:00、压缩消失、片尾时间与卡片一起还原；**↷ 重做**再次恢复延长后的状态。

### 冲突场景：新闻延长 7 分钟

把「新闻速览」改成 12:00：超时 7:00，缓冲 2:00 + 采访最多让出 3:00（6:00→下限 3:00）= 5:00，
**仍有 2:00 无法安放**。界面出现红色冲突卡，说明：缺多少、已经从哪里消化了多少、建议如何处置；
最近的环节被标红斜纹（被迫低于下限），而**固定点 10:15 纹丝不动，环节之间也不重叠**。

## 调度规则（`src/lib/schedule.ts`，纯函数）

固定开播点把节目切成一个个独立时间窗口，每个窗口独立结算：

1. **普通调整 → 整体顺延**：上一个环节结束即下一个开始。
2. **固定点是硬边界**：固定环节必须在指定时刻开始；固定点不会因为前后改动而移动。
3. 窗口超时（计划总时长 > 窗口宽度）时，按顺序消化：
   1. **先缓冲段**，可降到 0:00；
   2. **再可压缩环节**，不低于各自「压缩下限」；
   3. 两类来源都按**靠近固定点者优先**承担；
   4. 全部到下限仍放不下 → 生成冲突报告（原始超时、已消化量与来源、未解决量、中文原因），缺口落到离固定点最近的环节并标红。
4. 窗口内容不足时，固定点**不**提前，中间如实保留为「空闲等待」。
5. 任何结果都保证：`固定环节.start === pinnedStartSec`、相邻环节 `next.start >= prev.end`（测试里有不变量断言）。

## 操作说明

- **拖动排序**：拖拽每行左侧的 ⠿ 把手（dnd-kit）。
- **改时长**：点击「计划时长」输入框，支持 `m:ss`（`8:30`）、`h:mm:ss` 或纯分钟数，回车或失焦生效。
- **改压缩下限**：每行「下限」输入框（需先打开「可压缩」）。
- **固定开播点**：点「设固定点」默认钉在该环节当前的计划开播时刻；固定后可在其下方输入框精确修改（如 `12:30`），再点一次取消。
- **缓冲段**：`缓冲` 类型自动视为可降至 0:00，优先被消耗。
- **添加 / 删除环节**：列表底部与每行右侧。
- **播放头预演**：▶ 按真实时钟推进（可 1/2/4/8 倍速、拖动进度条、点击时间轴定位），当前播出环节在行内高亮。
- **撤销 / 重做**：按钮或 Ctrl/⌘+Z、Ctrl/⌘+Shift+Z（Ctrl+Y）。历史上限 100 步。

## 目录结构

```
src/
  types.ts                 数据模型（环节、调度结果、冲突报告）
  lib/
    schedule.ts            调度引擎：窗口切分、缓冲/压缩分配、冲突检测（纯函数）
    seed.ts                内置 30 分钟样例
    format.ts              时间格式化与 m:ss 解析
    theme.ts               深色导播台配色（已通过色盲/对比度校验）
  state/
    reducer.ts             past/present/future 三段式历史 + 所有编辑 action
    storage.ts             localStorage 读写与容错
    useRundown.ts          状态 hook（编辑 → 调度 → 持久化）
    usePlayback.ts         requestAnimationFrame 播放头
  components/
    Timeline.tsx           按秒比例时间轴：环节块/空闲/固定点旗帜/播放头
    StatsBar.tsx           KPI：总时长、总跨度、片尾结束、缓冲余量、冲突数
    ConflictPanel.tsx      绿色「已消化」明细 + 红色冲突原因
    SegmentList.tsx        可拖拽排序、可编辑的环节表
    Transport.tsx          播放控制
  test/                    vitest：调度引擎 / reducer / 端到端场景
```

## 测试覆盖

`npm test` 共 23 个用例：

- **时间传播**：样例基线时间、无固定点顺延、固定点后延长不影响前方、缩短保留空闲；
- **压缩分配**：采访 +4 分钟（缓冲吃光 + 采访压缩、片尾不变）、缓冲优先于压缩、
  多来源时靠近固定点优先、下限保护；
- **固定点冲突**：缓冲与下限耗尽后的未解决量、冲突文案、极端超时下固定点仍准点、双固定点独立结算；
  每个用例都附带「不重叠 + 固定点准点」不变量断言；
- **撤销 / 重做**：时间、缓冲、压缩与冲突随历史一起恢复，重做栈在新编辑后清空，
  排序 / 固定 / 时长钳制的历史行为；
- **端到端**：在真实 React 界面上改时长、读取消化卡片与缓冲余量、撤销/重做、
  冲突出现/消失、`localStorage` 持久化与刷新恢复。
